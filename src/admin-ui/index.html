Worlds

Schedule

When every world is backed up (local time of this machine). A world can have a schedule of its own (its cogwheel). A slot missed while the machine was off runs as soon as the service is back.

While a world is active in Foundry Foundry's /api/status says which world is launched. Backups of a launched world are consistent as long as nobody is changing it at that moment.

Foundry

Before a backup the service asks Foundry's /api/status which world is launched (see the active-world rule on the Schedule page). Enter the address Foundry answers on from this machine, usually http://localhost:30000. Backups run without it; only the active-world check needs it. Test asks the address in the field without saving it.

    GitHub

    The service pushes with this token and creates a private repository for a world that has none yet. It is never shown here. Before it expires, create a new one on GitHub and add it here: GitHub must accept it first, then it is used at once. Test setup checks the token, git, the data folder, Foundry and every world's repository.

      Repositories Creating needs a token with Administration: read and write on all repositories of its account; pushing needs Contents: read and write on the world repositories.
      Releases Every backup commit then also carries .github/workflows/release-world.yml (never written into the world folder). GitHub Actions turns each push into a release with world.json and world.zip for Foundry's Install World. The repositories are private, so Foundry installs through the Foundry release proxy; see the README.
